# QA Boot V0.1 — Detection Breadth Design Spec

Date: 2026-06-08
Status: Approved (pre-implementation)
Builds on: `docs/superpowers/specs/2026-06-02-qa-boot-v0-design.md` (V0, shipped).
Related: ADR 0001 (CLI useful without external services), ADR 0003 (QA Radar as
evidence provider), `docs/06-qa-radar-adapter.md`.

## Why

V0 validation (run read-only on four diverse real repos) found the scanners are
JS/Python-manifest-biased and systematically under-detect JVM / QA-automation
repos — the product's primary audience. Confirmed gaps:

- **JVM/Kotlin/Java test detection missing** — `gorillas` (Gradle/Kotlin, real
  JUnit tests) and `insider-qa` (Maven/Java, `src/test/java/`) both reported
  `test: (none)`.
- **Gradle/Maven build detection missing** — only npm/Make/Docker/fastlane covered.
- **Discoverability rubric counts only npm `build.command.*`**, so a Makefile+CI
  repo scored 1 instead of 3.
- **Silent QA Radar empty result** — `insider-qa` has zero commits, so qaradar
  errors → `[]` with no diagnostic.
- **`agent_permissions.config..claude`** double-dot id (cosmetic).

Key finding: **qaradar already does multi-language test *presence* mapping**
(Java/Kotlin/Swift/Go/Ruby/Rust patterns; as of 0.4.0 also Obj-C/Dart/RN +
Jest/Istanbul + monorepo coverage). It correctly counted the gorillas Kotlin test
(`files_with_tests: 1`). So qa-boot should **consume** that signal rather than
reimplement test-file finding. The genuinely qa-boot-only work is test-**stack**
characterization (which frameworks) and **build** detection — neither of which
qaradar emits.

## Scope

### In scope
1. Test-stack framework detection from build files (Gradle/Maven/npm).
2. Consume qaradar test-presence (`test_to_source_ratio`, `files_with_tests`).
3. JVM test-dir fallback (`src/test/`) for the no-qaradar case (ADR 0001).
4. Gradle/Maven build detection.
5. Maturity rubric fixes (discoverability build signal; test_signal qaradar signal).
6. QA Radar "ran but empty" diagnostic log.
7. `agent_permissions.config.*` id slug fix.

### Out of scope (deferred)
- Source-extension language fallback (no manifest → infer language). Fuzzy
  thresholds; revisit later.
- Workspace mode, `refresh`/`status`, told facts, `--base` diff mode (V1).
- Deep iOS project parsing (`project.pbxproj`); XCUITest is keyword-only.

## Architecture

Extends the V0 A′ vertical slices. No new architecture, no renderer changes (the
domain summaries are table-driven, so new `test.*` / `build.*` facts surface in
`test-stack.md` / `build-and-run.md` automatically).

## Components

### 1. Test-stack framework detection — `src/scanners/test-scanner.ts`

Approach A: keyword/substring matching on raw build-file text (consistent with the
existing `[tool.pytest]` regex on `pyproject.toml`; no AST, no execution).

- Read (when present): `build.gradle`, `build.gradle.kts`, `pom.xml`,
  `settings.gradle(.kts)`. (`package.json` deps already handled.)
- Match a `FRAMEWORK_KEYWORDS` table (case-insensitive substring) → emit
  `test-framework` evidence with `detail.source = "build-file"`:

  | Keyword(s) | Framework |
  |---|---|
  | `junit`, `org.junit` | junit |
  | `testng` | testng |
  | `rest-assured`, `restassured`, `io.rest-assured` | rest-assured |
  | `selenium`, `seleniumhq` | selenium |
  | `selenide` | selenide |
  | `cucumber` | cucumber |
  | `appium` | appium |
  | `espresso` | espresso |
  | `xcuitest` | xcuitest |
  | `k6` | k6 |
  | `jmeter` | jmeter |
  | `gatling` | gatling |

- Dedup by framework name (same `seen` set as today; config/dep sources still win
  ordering is irrelevant — first match per name).
- Add `src/test/` to `TEST_DIRS` (Gradle/Maven convention) so the test-dir
  fallback fires for JVM repos even without qaradar.

`test-facts.ts` maps `test-framework` evidence with `source: "build-file"` as
`provenance: inferred`, `confidence: 0.5`, with limitation "Detected from a build
file; not confirmed to run." (Same treatment as `source: "dependency"`.)

### 2. Consume qaradar test-presence — `src/providers/qaradar-parse.ts` + `src/domains/test-facts.ts`

- `parseQaradar(report)` returns up to **two** `EvidenceResult`s:
  - the existing `repo_quality` result (risk), and
  - a new `test` result when `summary.source_files > 0`, carrying
    `value = { test_to_source_ratio, files_with_tests, files_without_tests,
    source_files, test_files, coverage_status }`, `confidence: 0.8`,
    `evidence: ["qaradar test-to-source mapping"]`,
    `statement: "QA Radar mapped tests to source files."`.
- New `qaradarTestFacts(results, today)` in `test-facts.ts` maps the `test`
  `EvidenceResult` → one fact:
  - id `test.coverage-shape`, domain `test`, provenance `observed`, confidence 0.8,
    `value` = the mapping summary above,
    statement e.g. `"QA Radar: <files_with_tests>/<source_files> source files have
    mapped tests (ratio <test_to_source_ratio>)."`,
    limitations `["Mapping is name/convention based, not execution-verified."]`.
  - Returns `[]` when no `test` result present.

### 3. Gradle/Maven build detection — `src/scanners/build-scanner.ts`

Add `build-file` evidence:
- `build.gradle` / `build.gradle.kts` / `gradlew` / `settings.gradle(.kts)` →
  `{ name: "gradle" }` (emit once).
- `pom.xml` / `mvnw` → `{ name: "maven" }` (emit once).

`build-facts.ts` already maps `build-file` → `build.tool.<name>` (observed, 0.8);
no mapper change needed.

### 4. Maturity rubric — `src/maturity/rubric.ts`

- **Discoverability** build signal: count `build.command.*` **OR** `build.tool.*`
  (so Make/Gradle/Maven repos get the build signal).
- **Test signal**: `hasTests` becomes true if any `test.framework.*` /
  `test.directory` **or** a `test.coverage-shape` fact with `files_with_tests > 0`.
  Coverage signal true if `test.coverage-tool` **or** the `test.coverage-shape`
  `coverage_status === "ok"`. (qaradar's mapping now feeds the score, fixing JVM
  repos where qa-boot's own scanner found no JS/py tests.)

### 5. QA Radar diagnostic — `src/pipeline/run-scan.ts`

In the qaradar block, when `isAvailable()` is true but `collect()` yields an empty
result set, log: `"QA Radar ran but found no usable data (e.g. no commits or no
risk signals). Continuing with built-in scanners."` (distinct from the existing
"not available" message). The `repo_quality.risk-analysis` unknown still records
the gap. Also wire `qaradarTestFacts(results, today)` into the fact set.

### 6. Agent-config id slug — `src/domains/agent-facts.ts`

Slugify the marker name for the fact id only (keep the human name in the
statement): lowercase, strip leading dots, replace `.`/spaces with `-`.
Examples: `.claude` → `agent_permissions.config.claude`,
`CLAUDE.md` → `agent_permissions.config.claude-md`,
`.cursorrules` → `agent_permissions.config.cursorrules`. The rubric's
`agent_permissions.config.` prefix check is unaffected (still a prefix match).

## Fixtures (new)

- `test-fixtures/repos/gradle-junit/`: `build.gradle.kts` with
  `testImplementation("org.junit.jupiter:junit-jupiter")` and
  `testImplementation("io.rest-assured:rest-assured")`,
  `src/test/kotlin/AppTest.kt`, `README.md`.
- `test-fixtures/repos/maven-selenium/`: `pom.xml` with `junit` and
  `org.seleniumhq.selenium` dependencies, `src/test/java/AppTest.java`.

## Testing

- **test-scanner**: gradle-junit fixture → `test-framework` evidence for
  `junit` + `rest-assured` (source build-file); `src/test/` → `test-dir`. maven
  fixture → `junit` + `selenium`. Bare repo → still none.
- **build-scanner**: gradle/maven fixtures → `build-file` `gradle`/`maven`.
- **qaradar-parse**: the committed `fixtures/qaradar/sample.json` → now yields a
  `test` EvidenceResult with the coverage-shape value (plus the existing
  repo_quality). Empty-summary report → no `test` result.
- **qaradarTestFacts**: `test` EvidenceResult → `test.coverage-shape` fact;
  `[]` for none.
- **test-facts**: build-file-sourced framework → inferred/0.5.
- **rubric**: a Makefile/Gradle-only repo (build.tool, no build.command) scores
  discoverability ≥ 3; a repo with only a `test.coverage-shape` (files_with_tests
  > 0) and CI scores test_signal ≥ 3.
- **agent-facts**: `.claude` marker → id `agent_permissions.config.claude`.
- **End-to-end re-verification** (manual, like V0 Task 25): probe (read-only) the
  real `gorillas` (Gradle/Kotlin) and `maven`/`insider`-style repos and confirm
  test frameworks + build tool + qaradar coverage-shape now appear.

## Acceptance criteria

1. A Gradle/Kotlin repo with JUnit + RestAssured in `build.gradle.kts` produces
   `test.framework.junit`, `test.framework.rest-assured`, `test.directory`
   (`src/test`), and `build.tool.gradle`.
2. A Maven/Java repo with JUnit + Selenium produces the equivalent + `build.tool.maven`.
3. When qaradar ran, a `test.coverage-shape` fact carries its mapping summary and
   feeds `test-stack.md` + the test_signal rubric.
4. Discoverability scores the build signal for Make/Gradle/Maven repos.
5. When qaradar runs but returns nothing, the CLI logs the "ran but no usable
   data" diagnostic and the scan still succeeds.
6. Agent-config fact ids have no double-dot.
7. All existing V0 tests still pass; new detection is unit-tested; renderers are
   unchanged.
